# Architecture rules
- Keep owner-only live payment trials behind server-verified role and account checks while beta remains enabled; use provider-hosted checkout so the app never collects trial card data. The current owner trial uses Stripe and verifies the live account and pack prices before opening checkout.
- Fulfill verified Stripe sessions through a service-only transaction under the shared user lock, validating paid EUR amounts and recovering retries without duplicate credits.
- Fulfill verified PayPal captures in one service-only database transaction under the shared user lock, recovering completed orders idempotently to avoid lost or duplicate credits.
- Keep the landing presentation experiment behind `LANDING_EXPERIMENT_ENABLED`, preserving the legacy landing independently, so reverting presentation does not alter account data or business rules.
- Use the same experiment switch for the Love display-name override and direct landing authentication links; keep the stored mode identifier unchanged so existing picks and matches remain available.
- Authenticate database match callbacks with a private, per-match, single-use token; check live bilateral blocks in both match reads and notification delivery to prevent forged callbacks and stale contact access.
- Require verified profile emails for email-based matching and reset verification on email changes so mailbox identity cannot be claimed through editable profile fields.
- Charge replacement-pick credits inside the insert transaction with a per-user lock; never separately debit in the client so direct inserts cannot bypass payment or charge twice.
- Restrict simulated credit fulfillment to server-verified administrators; normal users must not receive paid credits from test purchases.
- Never collect card details in simulated purchases; use a card-free administrator confirmation so test flows cannot solicit real financial data.
- Apply referral codes only during Auth-triggered profile creation and make referral attribution immutable afterwards to prevent post-signup credit claims.
- Share an exact project-origin allowlist for checkout returns; never trust Origin or a hosting-domain wildcard as a payment destination.
- Define the authentication context in its own non-component module so hot updates to the provider and consumers retain the same context identity.
- Enforce match uniqueness by the unordered pick-ID pair, not the user-ID pair, so new mutual choices preserve historical matches without duplicating the same event.
- Resolve each match's own pick through an authenticated match-scoped RPC so repeated matches keep their original names and modes without exposing the other participant's pick.
- Store selection retention and expiration on picks and perform replacements in the insert trigger under the existing user lock; protect these fields against direct updates so fees and capacity cannot be bypassed.
- Derive expired selection visibility and matching eligibility from timestamps without recurring jobs; retain expired rows solely for existing match history.
